# 🛡️ SIEM Home Lab — Detection Engineering

A hands-on SIEM lab built to practice **security monitoring, log analysis, attack simulation, and detection engineering** using the Elastic Stack, Sysmon, and Atomic Red Team.

## 🔎 Overview

This project simulates a small blue-team/SOC environment where adversary techniques are executed against a Windows 11 virtual machine, logged by Sysmon, forwarded through Winlogbeat, and analyzed in Kibana.

The goal was to gain practical experience with the process of:

**Simulate → Collect → Analyze → Detect → Validate**

## 🎯 Detection Use Cases

### 1. Suspicious PowerShell Execution

**MITRE ATT&CK:** T1059.001 — PowerShell

**Detection:**

```text
event.code:1 and process.name:"powershell.exe" and process.args:"-e"
```

The detection identifies PowerShell execution using an encoded-command flag.

**Confidence:** High

The combination of PowerShell execution and an encoded command is relatively uncommon during routine system administration and can indicate an attempt to obscure command contents.

---

### 2. System Information Discovery

**MITRE ATT&CK:** T1082 — System Information Discovery

**Detection:**

```text
event.code:1 and process.name:"systeminfo.exe"
```

The detection identifies execution of `systeminfo.exe`, which can be used to gather information about the operating system and host.

**Confidence:** Low

This activity can occur during both legitimate administration and malicious reconnaissance, making the process alone difficult to classify as malicious.

**Potential improvement:** Incorporate additional contextual information, such as the source and surrounding process activity, to reduce false positives.

---

### 3. Registry Run Key Persistence

**MITRE ATT&CK:** T1547.001 — Registry Run Keys / Startup Folder

**Detection:**

```text
event.code:"13" and registry.path:*CurrentVersion\\Run*
```

The detection identifies modifications to Windows Registry Run keys, which can be used to establish persistence.

**Confidence:** Medium

Registry writes to these locations are less common than routine commands such as `systeminfo`, but legitimate software installations can also modify Run keys.

## 🔧 Challenges & Troubleshooting

### VirtualBox Network Connectivity

The Windows VM initially could not reach Elasticsearch running on the host.

I learned that VirtualBox NAT uses `10.0.2.2` as the host gateway from the VM rather than `localhost`.

### Windows Firewall

Windows Firewall initially blocked inbound traffic to Elasticsearch on port `9200`.

An inbound firewall rule was added to allow the required traffic from the lab environment.

### Windows Defender & Atomic Red Team

Windows Defender detected and interfered with Atomic Red Team test files during installation and execution.

Because Atomic Red Team intentionally contains attack simulations, this behavior was expected. The testing was performed inside an isolated virtual machine rather than on a personal or production system.
